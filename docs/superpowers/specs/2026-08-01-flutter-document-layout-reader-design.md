# Flutter 原版式点读阅读器设计

## 目标

将已经确认的 Web 演示迁移到 Flutter 正式应用。阅读页面必须优先呈现文档本身，点击层只负责识别单词，不把英文内容重新抽取成独立句子列表。

## 已确认的交互

- 小于 600dp 的手机界面使用底部翻译卡；翻译卡打开时不替换文档，只覆盖文档下部，并可关闭。
- 大于等于 600dp 的平板界面默认使用右侧翻译栏，并允许切换为悬浮卡。
- 悬浮卡位于文档上方，可在文档可视区域内拖拽；任何屏幕尺寸或方向变化后都必须重新限制在可视范围内。
- 平板记住“侧栏/悬浮”模式和悬浮卡相对位置；不同文档共享该阅读偏好。
- 正文、文档标题和副标题/章节标题中的英文单词均可点击。
- 作者、单位、页码、图表和图片内容不建立单词点击区。
- 选中单词显示高亮、释义、音标、发音入口和收藏能力；再次选择其他单词直接刷新同一张词卡。
- 所有点按目标保持至少 48×48dp；透明点击区可扩大命中范围，但不得改变原文字的排版和绘制。

## 格式策略

### PDF

使用 `pdfrx` 2.4.7 作为唯一 PDF 页面引擎。`PdfViewer.file` 渲染本地沙箱中的原始页面；页面文字 API 提供字符/片段坐标；阅读器把英文单词范围映射为页面坐标，并通过透明交互区域完成点击。PDF 页面图像、字体、表格和排版均由 PDF 引擎绘制，不在 Flutter 中重排。

PDF 解析导入仍负责格式校验、加密/损坏/扫描件错误和文档库状态。阅读时的页面文字和坐标由 `pdfrx` 按需获取，不把坐标持久化到 Drift，避免缩放、旋转和不同设备尺寸造成缓存失效。

### DOCX

DOCX 采用高保真重排，不宣称像素级复刻 Word。解析并保存段落样式、标题层级、列表类型以及基础行内样式；阅读时按文档顺序绘制可点击文字。标题、副标题和正文可点击，作者/单位等普通元数据仅在能可靠识别时排除。

### TXT

TXT 保持自然段和空行结构，按正文样式重排，所有英文单词可点击。

## 统一模型

`StoredReaderDocument` 增加 `format`、`localPath` 和按顺序排列的 `StoredReaderBlock`。每个 block 持有段落样式及其句子；现有 `StoredReaderSentence`、`StoredReaderToken` 继续作为词典查询、短语识别和阅读位置保存的稳定标识。

PDF 的可视单词使用运行时 `PdfWordHitTarget`，包含页码、文字、上下文、字符范围和页面坐标。选择后转换成统一的 `ReaderSelection`，翻译层无需知道来源是 PDF 还是重排文档。

## 状态与持久化

`ReaderController` 负责文档、选择、翻译和阅读位置。`ReaderCardPreferences` 负责平板词卡模式和归一化位置，使用现有 `AppSettings` 表保存，不修改数据库 schema。

PDF 阅读进度保存当前页码和该页内偏移；DOCX/TXT 沿用段落/句子/局部偏移。旧的阅读位置仍可读取，找不到目标时回退到文档开头而不是报错。

## 错误与性能

- 本地文件丢失时显示可恢复的“源文件不可用”状态，不崩溃。
- 加密、损坏和扫描 PDF 使用现有稳定错误类型。
- PDF 文字坐标按可见页懒加载并缓存；离开文档后释放。
- 点击层不逐字创建常驻 Widget；按页聚合命中区域，并只为可见页面保留数据。
- 所有文档和词典处理保持离线，不新增网络权限或上传行为。

## 验收

- 手机 412×915：打开文档、点击标题词和正文词、底部词卡出现并可关闭。
- 平板 1280×800：默认右侧词卡；切换悬浮后可拖拽且不越界；旋转后仍在文档区域内。
- PDF：页面视觉与原文件一致，缩放/滚动后点击词仍命中正确。
- DOCX：标题、列表和正文层级可辨识，标题与正文中的词均可点击。
- TXT：自然段不被拆成独立卡片或句子列表。
- 原有生词、短语、发音、自动收录和阅读进度功能继续通过测试。
